# 论文写作总则

> 适用于 CUMCM 及同类数学建模竞赛论文。

---

## 一、结构与章序（固定八段）

```
摘要（+ 关键词，独占一页）
一、问题重述
二、模型假设与符号说明      ← 假设 H1..Hn + 符号表（表2-1）
三、模型建立               ← 3.1 前放 AI 声明块
四、模型求解               ← 算法设计 + 收敛曲线（图4-1）
五、结果与分析             ← 5.1 问题1 / 5.2 问题2 / 5.3 问题3 / 5.4 敏感性
六、模型评价与改进         ← 优点 / 缺点 / 改进方向
七、参考文献
八、附录                   ← 8.1 支撑材料列表 / 8.2 核心源码 / 附：符号与口径核对说明
```

- 顶级标题**中文数字**（一、二、三…），子节 `1.1` / `2.1` / `3.1`
- 摘要后必须有「关键词」，**单独一页不掺其他内容**（关键词后插 `\newpage`，并去掉 `--toc`）

## 二、假设与符号

### 假设（H1…Hn）书写规则
- 每条假设一行，**带编号**（`**H1**` 形式，不再套 `1. 2. 3.`，避免双重编号）
- **假设必须与求解器实现一致** —— 这是最容易出的硬伤

> **真实案例**：草稿 H2 写"需求不可拆分"，但求解器实际允许拆分配送（SDVRP），
> 且单客户最大需求 12198 kg ≫ 3000 kg 车容，物理上必须拆分。
> → 模型描述与代码矛盾，属于**方法论硬伤**，必须二选一统一。
> 修法：H2 改为"允许拆分配送"，约束 (10) 由 `Σy=1` 放宽为 `≥1`，
> 并在 3.2.2 / 4.2 节说明解码器按容量分包。

- 每条假设写完后**回查代码**确认一致

### 符号表（表2-1）
- 三列：符号 / 含义 /（单位，可选）
- 全文符号**唯一定义、不重复、不冲突**
- 定稿前跑一遍：符号表中每个符号都在正文出现过，正文每个符号都在表里有定义

## 三、公式

- 显示公式用 `$$...$$`，编号用 `\tag{N}`
- **Word 路径不支持 `\tag{}`** → 转 docx 前先 `\tag{N}` → `\qquad\text{(N)}`（见坑清单）
- 公式内**连续中文必须包 `\text{}`**（元/辆/度/单/位），否则 xelatex 丢字
- 正文**裸希腊字母**必须包 `$...$`，否则西文字体丢字

---

## 四、图表

| 项 | 规则 |
|---|------|
| 编号 | `图X-X` / `表X-X`（X = 章号），**分章编号**，禁止 `图1` |
| 位置 | 图在下、表在上 |
| 题注 | 居中；图下去 `Figure N:` 前缀 |
| 引用 | 「如图 X-X 所示」「如表 X-X 所示」，禁写 `见 xxx.png` |
| 中文化 | 轴标签 / 图例 / 标题全中文，`plt.rcParams["font.family"]=["SimHei",...]` |
| 图例取值 | 注意 `solver.FLEET[k][1]` 是布尔，`[0]` 才是中文名（踩过） |

### 画图的可读性硬要求
**"对比"图必须有视觉对比度。** 两值差 0.7% 时并列等高柱看不出任何差异，评委直接判定"没做分析"。

**解决方案（三幅子图）**：
1. **(a) 绝对量级 + 截断纵轴** —— 纵轴自略低于最小值起，标"纵轴自 X 起"，加 Δ 标注
2. **(b) 相对变化率 %** —— 多指标 % 柱，红=升 / 蓝=降，附"原值→新值"
3. **(c) 结构对比** —— 并列柱（如燃油车 vs 新能源车），标题带占比变化

参考实现 `03_流水线与脚本/scripts/fig_compare.py`。

## 五、数值与口径

1. **全文数字唯一来源**：求解器输出（`numerical_results.md`），不手抄、不估算
2. **口径必须统一**：如"98 列表客户 / 88 有效客户"，正文从头到尾用同一口径，并在首次出现时说明
3. **异常值要主动交代**：如"车型3（燃油C）实启 0 辆"必须在正文注明，不能默默略过
4. 交付前逐数字与求解器输出对账（见 `06_质检与验收/法证型审计.md`）

## 六、参考文献

- 编号 `[1]..[n]` 连续，正文有对应引用
- **必须含 AI 工具条目**（见 `01_官方红线与合规/AI合规三件套.md`）
- 格式统一：`[编号] 作者. 题名[文献类型]. 刊名, 年份, 卷(期): 起止页.`

## 七、模型评价（第六章）写法

**优点**要具体、可验证，不自吹：
- 贴合实际、约束完备（列出纳入了哪些真实因素）
- 目标综合、口径清晰
- 算法有效（用收敛曲线 / 耗时数据支撑）

**缺点**要诚实 —— 评委会自己发现，主动写出来反而加分：
- 本次真实案例：收敛曲线是水平线（初始种子已是全局最优，GA 90 代未超越）
  → 不掩盖，主动写成"构造式初始化有效"的优点 + 在改进里说"可引入更强扰动算子以体现搜索过程"

## 八、写作分层原则（模拟 vs 正式）

| 类型 | 例子 | 处理 |
|------|------|------|
| **方法论硬伤**（必改） | 数据泄露、假设与代码矛盾、复算口径不一致、弱信号编造 | 必须修，错了 = 学到错误知识 |
| **呈现层细节**（模拟可放） | 附录清单与 zip 对齐、小数位数、个别乱码、文献格式 | 模拟阶段可放过，正式交付再精修 |
