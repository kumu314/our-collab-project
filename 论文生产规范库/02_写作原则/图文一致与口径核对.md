# 图文一致与口径核对

> **核心原则：图注、正文、代码、数据文件四者数字必须一致。换任何一处的口径，四处同步。**
> 不这么做 = 自造图文矛盾，评委一眼看出，直接判定论文不可信。

---

## 一、真实事故：收敛曲线图文打架

**过程**：
1. 原 `convergence.png` 画的是"历史最优 running-best"，从 gen0 到 gen90 恒为 76832.06 → **两条水平线**
2. 用户问"这两个横线是……？" → 诊断：初始种子（角度序 + 贪心最大车型）已是全局最优，CA-IGA 90 代未超越
3. 改画"每代可行解种群均值"（`conv_mean`），曲线变成真实下降形态（80185 → 79657）
4. **但图注和正文没同步改** → 曲线停在 ~79500，正文还写"最优值 76832.06"
5. 用户/评委视角：数字对不上，论文自相矛盾

**正确修法（四处同步）**：
- 图注改为：
  > 图4-1 CA-IGA 收敛曲线（实线：每代可行解种群平均成本；虚线：搜索到的最优总成本）
- 图**前**加一段说明文字：
  > 均值在前 10 代由 80185 快速降至约 78700 后趋稳；虚线为搜索到的最优总成本，
  > 因构造式初始化已产生全局最优个体，该值自第 0 代起即为水平线。
- 把它**写成优点**："构造式初始化有效"
- 正文引用处同步

**教训沉淀**：**换画图口径后必须同步图注 + 正文解释，否则自造图文矛盾。**

## 二、四处一致性检查表

| 处 | 检查什么 | 怎么查 |
|---|---------|-------|
| **图注** | 图的量与正文描述是同一个量 | 人工读一遍图注 vs 看图 |
| **正文数字** | 与求解器输出逐位一致 | 脚本对账（见下） |
| **附录代码** | 是磁盘上真实跑的那份 | `sync_appendix_pdf.py` 同步 |
| **数据文件** | `numerical_results.md` 里的数字 = 图 = 正文 | grep 数字反查 |

| 口径 | 冲突 | 统一为 |

## 四、异常值处理：宁可主动交代，不要默默略过

评委一定会注意到异常。两种写法，效果天差地别：

- ❌ 沉默：正文不提"车型3 实启 0 辆"，评委自己发现 → 怀疑你没检查
- ✅ 主动：5.1 正文写"车型 3（燃油 C 小型车）实际启用 0 辆，原因是大容量车型（3000 kg）优先被选中" → 显得你核查过

**同理适用于**：
- 收敛曲线是水平线 → 主动解释 + 写成"构造式初始化有效"的优点
- 敏感性曲线有拐点 → 说明拐点出现的物理原因
- 某方案明显劣于另一方案 → 说明为什么

## 五、代码 ↔ 论文 同步机制

**问题**：改了 `solver.py` 后，附录里嵌的代码还是旧快照。

**解决**：`sync_appendix_pdf.py`
- 把磁盘最新的 `solver.py` / `run_all.py` 注入**两份** md（`论文_定稿版.md` 和 `论文_定稿版_pdf.md`）的附录代码块
- 定位标记：`**solver.py**` → `**run_all.py**` → `### 8.3`
- **改完源码必须重跑这个脚本再出稿**

实测输出：`solver.py 20311 字符 / run_all.py 18756 字符 已同步`

## 六、数字对账脚本思路（法证型审计）

```python
# 从求解器输出读权威数字
import json, re, pathlib
truth = {...}   # numerical_results.md 里的值

# 从论文 md 里 grep 每个数字
paper = pathlib.Path("论文_定稿版.md").read_text(encoding="utf-8")

for key, val in truth.items():
    hits = paper.count(str(val))
    print(f"{key:20s} {val:>12} 出现 {hits} 次", "OK" if hits >= 1 else "❌ 缺失")
```

**原则**：论文里出现的每个关键数字，都能在 `numerical_results.md` 里找到同源值；
找不到 = 手抄/估算/编造，必须修。
