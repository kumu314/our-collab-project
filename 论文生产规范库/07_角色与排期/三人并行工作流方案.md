# 三人并行工作流方案

> 原始方案：`D:\WorkBuddy_output\数模并行工作流\数模三人并行工作流方案.md`
> 本文件在原方案基础上，补进了 2026-09 两次模拟演练的实战修正。

---

## 一、核心机制：闸门件前置

**问题**：原流程串行（队长写 → 代码手跑 → 论文手最后排版），
代码手/论文手大量闲置，初稿常拖到最后一天前夜。

**解法**：把「框架 / 假设 / 符号 / 大纲」设为**闸门件《建模骨架 v0.1》**，
由队长 + agent 在 **Day1 0–6h** 单独冲刺产出，**发出后三人立刻并行**。

骨架 v0.1 必须包含：
1. 问题理解
2. 模型思路草稿
3. **假设清单**（H1…Hn）
4. **符号表**
5. section 大纲
6. **"需要算什么"清单**（输出需求）—— 这条最关键，代码手靠它开工

> 队长不需要很懂建模：让 agent 先生成，队长做**取舍判断**即可。

## 二、三人角色（重定义）

| 角色 | Day1 上午（被闸门卡住） | Day1 下午起 | Day2 | Day3 |
|------|----------------------|-----------|------|------|
| **队长**（建模 + agent 驾驶） | 冲《建模骨架 v0.1》 | agent 写方法稿 + 审代码中间结果 | 定模型方向 + 写分析稿 + 联调 | 统稿终审 |
| **代码手** | 搭环境 / 找数据 / 读题 | 按"输出需求"写代码骨架 | 出主结果 + 敏感性 + 备选 + **所有图/表** | 补实验 + 修订 |
| **论文手** | 建共享文档 + 格式模板 | 建论文骨架（标题/假设/符号表/引言占位） | 填方法 + 结果段 → **完整初稿** | 统稿 + 格式 + 提交 |

**角色升级（关键）**：
- 代码手不只是"跑代码" → 独立负责**敏感性分析、备选模型、全部图/表生成**
- 论文手不只是"最后排版" → **Day1 就建骨架并填框架性内容**，越填越顺

## 三、Day1–Day3 看板

| 时段 | 队长 | 代码手 | 论文手 | 协作点 |
|------|------|-------|-------|-------|
| Day1 0–3h | 启动 agent 出骨架 | 搭环境、找数据、列数据需求 | 建共享文档 + 格式模板 | 15min 对齐选题分工 |
| Day1 3–8h | **发出骨架 v0.1** | 按"输出需求"写代码骨架 | 按大纲建论文骨架 | 骨架入共享文档 |
| Day1 8–24h | agent 写方法稿、看中间结果 | 跑通主模型出第一版结果 | 填引言/假设/符号表，留方法/结果占位 | 评论/@ 同步 |
| Day2 0–12h | 定模型方向 + 写分析稿 | 出主结果 + 敏感性 + 备选 | 填方法段 + 结果段 | 图/表即出即插 |
| Day2 12–24h | 联调 + 补分析 | 补图/表 + 收尾实验 | 汇总 = **完整初稿 ✅** | **初稿交付点** |
| Day3 0–结束 | 终审 | 补实验/改图 | 统稿 + 格式 + 提交 | **只修订不创造** |

## 四、协作工具

- **共享文档**：腾讯文档 / 乐享，实时多人编辑，**禁止来回传文件**
- agent 产物（骨架、方法稿）**直接贴进共享文档对应 section**，两人即时可见
- **评论/@ 代替开会**；每晚一次 15min 对齐足够

### 腾讯文档协作版式
`make_tencent_doc.py` 会给每个 section 加 `【owner | 填稿时段】` 标注
（本次 30 个 section），可直接导入腾讯文档并行填稿。

## 五、演练暴露的三个协作断点（务必规避）

### 断点 1：统稿时才发现假设与代码矛盾
- **现象**：草稿 H2 写"需求不可拆分"，求解器实际是 SDVRP
- **代价**：Day2 末才修，牵动约束 (10) + 3.2.2 + 4.2 三处
- **规避**：**骨架发出当天**，代码手就要逐条确认"这条假设我能实现吗"，
  不能实现的**立刻反馈改假设**，不要自己默默按另一套写

### 断点 2：数字没回填，placeholder 满天飞
- **现象**：`论文草稿.md` 里全是 `{{RESULT_*}}` / `{{FIG_*}}` 占位符
- **解法**：`fill_draft.py` 批量回填（本次一次填完）
- **规避**：约定**数值占位符的命名规范**（`{{RESULT_<量名>}}`），
  代码手出结果后**立刻**跑回填脚本，不要等到统稿

### 断点 3：口径两个来源打架
- **现象**：草稿写"绿色区 30 客户"，实际数据 12 活跃客户
- **规避**：**凡是题面给的数与真实数据算出来的数冲突时，以真实数据为准，
  并在正文主动注明差异**（本次："按真实坐标核算，并非题述 30 个"）——
  评委看到这种交代是加分项
