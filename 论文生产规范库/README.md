> **建成**：2026-09-03 | **演练样本**：2026 暑期集训模拟二 C 题《城市绿色物流配送调度》（HFVRPSTW）
> **维护原则**：新踩一个坑 → 立刻写进 `04_坑与避雷`；新增一个可复用脚本 → 同步进 `03_流水线与脚本/scripts`。

## 二、60 秒速查（最硬的几条）

### 硬红线（违反 = 取消资格）
1. 附录**必须**含「支撑材料文件列表」+「全部可运行源码」，缺一即取消评奖资格。
2. AI 合规**三件套**缺一不可：正文逐处标注 + 参考文献列 AI 工具条目 + 支撑材料附《AI 工具使用详情》PDF。
3. 正文**禁出现**校名、赛区、队员姓名、指导教师。
4. 源码**必须可运行**（`py_compile` 全过是底线），且附录代码 = 磁盘上真实跑的代码。

### 最容易翻车的 5 件事
1. **pandoc `-t docx` 会吞掉所有 raw_tex**（`\begin{center}` 等）→ 题注整段消失。详见 `04_坑与避雷/pandoc-docx坑.md` 坑 1。
2. **pandoc 注入的 `\lstset` 会覆盖你在 header 写的高亮配置** → PDF 代码全黑。修法：用 `\AtBeginDocument{\lstset{...}}` 包裹。
3. **`results_cache.pkl` 存在时 `run_all.py` 只加载不重算** → 改了代码却拿不到新结果。必须先 `rm results_cache.pkl`。
4. **换画图口径后忘了改图注** → 自造图文矛盾（曲线停在 79500，正文写 76832）。
5. **Glob 工具有索引盲区**（Desktop 搜不到）→ 误判"数据不存在"。找文件优先用 Bash `ls`/`find`。

### 两条完整命令（改完 md 直接跑）
```bash
# PDF（官方提交件）
bash build_pdf.sh

# Word（审稿用）
bash build_docx.sh
```
详见 `03_流水线与脚本/主流水线.md`。

## 三、本库的「原则层」（比操作更重要）

1. **永远改源 md，永远别直接改 docx。** 改源重跑 = 3 秒安全；直接改 docx = 11 次覆盖、20 张图丢失、表号全错。
2. **法证型审计是最后一道关。** 交付前必须把论文里每个数字和求解器输出对账，跳过 = 埋雷。
3. **不造假、不编数。** 跑不动就报告卡点 + 列可选项 + 等用户拍板，禁止默默转向补别的事或自创替代方案。
4. **图文口径必须自洽。** 图注、正文、代码、数据文件四者数字必须一致，换口径要四处同步。
5. **模拟 vs 正式分层。** 方法论硬伤（数据泄露、口径矛盾、公式与代码不符）必改；呈现层细节（小数位、个别格式）模拟阶段可放。

## 四、典型使用路径

**场景 A：新赛题从零开始**
→ `07_角色与排期`（定闸门件）→ `01_官方红线与合规`（知红线）→ `02_写作原则`（写稿）→ `03_流水线与脚本`（出稿）→ `06_质检与验收`（交付）

**场景 B：已有 md，只要出 PDF + Word**
→ `03_流水线与脚本/主流水线.md`（照抄命令）→ `04_坑与避雷`（报错时查）→ `06_质检与验收`（验收）

**场景 C：用户反馈"PDF 对、Word 错"**
→ 直接开 `04_坑与避雷/pandoc-docx坑.md`，90% 是 raw_tex 被吞或 lstset 被覆盖。

**场景 D：用户反馈"论文里出现了不该出现的东西"**
→ `01_官方红线与合规/禁用词与不当内容清单.md` + `06_质检与验收/残留扫描脚本与命令.md`，跑一遍 grep 全扫。
