# 数模论文 · 多 Agent 协作仓库

> 三个人 + 三个 agent，并行写数模论文的协作基地。Git 分支隔离，看板同步状态，规范库统一标准，PR 合并成果。

---

## 这是什么

一个为数学建模竞赛论文打造的多人协作仓库。核心目标：

- **三个人各干各的，最后能拼到一起**
- **输出风格统一**，不用花大量时间改格式
- **谁在做什么一目了然**，不靠聊天传状态

---

## 快速开始（新队友进来先看这个）

### 1. 克隆仓库

```bash
git clone https://github.com/kumu314/our-collab-project.git
cd our-collab-project
```

### 2. 设置你的身份

```bash
# 复制模板
copy AGENT_ID.example AGENT_ID

# 编辑 AGENT_ID，改成你的代号（英文、小写、无空格）
# 比如：alice
```

### 3. 配置 Git 用户名

```bash
git config user.name "你的名字"
git config user.email "你的邮箱@example.com"
```

### 4. 读三份文档

开工前必读这三个：

1. `规范库/01_官方红线与合规/官方硬约束.md` — 知道什么不能碰
2. `docs/agent-workflow.md` — 知道协作流程怎么走
3. `STATUS.md` — 知道现在谁在做什么

## 协作流程（7 步走）

每个 agent 接到任务后按这个来：

1. **同步 & 读看板** — `git pull` + 看 `STATUS.md`
2. **认领任务** — 建分支 + 更新看板
3. **理解接口约定** — 搞清楚输入输出，别边猜边做
4. **干活** — 只在自己的分支、只碰自己的模块
5. **更新进度** — 每个里程碑更新一次看板
6. **提交 PR** — 推分支 + 发起 PR + 移到待评审
7. **响应评审** — 改完合并，任务移到已完成

详细步骤见 `docs/agent-workflow.md`。

---

## 核心原则

1. **看板唯一真相源**：谁在做什么，只看 `STATUS.md`，不靠聊天
2. **一人一分支**：每个 agent 在自己的分支干活，互不干扰
3. **模块化拆活**：按章节/模块拆任务，每人交一个完整零件
4. **规范库统一标准**：所有产出以 `规范库/` 里的要求为准
5. **先定接口再开工**：模块之间的衔接处先写死，内部实现自由
6. **整合人制**：有一个最终把关的角色，负责合并和统一风格

## 常见问题

**Q: 两个人改了同一个文件怎么办？**
A: Git 会提示冲突。谁后提交谁先尝试解决，解决不了找整合人。关键是拆任务时尽量避免多人碰同一文件。

**Q: 我想看看别人做到哪了？**
A: 看 `STATUS.md` 最直接。想看代码的话：`git fetch origin` 然后 `git log origin/agent/<对方id>/<分支名>`。

**Q: 输出风格差异太大合不到一起怎么办？**
A: 开工前先读 `规范库/` 里的相关规范。如果差异已经产生，由整合人在评审阶段统一调整。

**Q: 可以多个人用同一个 agent 账号吗？**
A: 不建议。身份乱了看板就没用了。每个操作者一个 `AGENT_ID`。
