# 角色分工（ROLES）

> **三个人 = 三个角色，一一对应。** 你的分支名、产出目录、看板分区都从这里来。
> 认领方法：pull 后在自己那一行填上姓名 + GitHub 账号，提 PR 合入。

| 角色 id | 谁 | 负责 | 产出落在 | 认领人 |
|---------|---|------|---------|--------|
| `modeler` | 建模手 | 模型、假设、符号表、**FACTS 数字口径**、统稿、合 PR | `00_CONTRACT/` + `scripts/` + `01_OUTBOX/modeler/` | kumu314（仓库创建者 / 管理员） |
| `coder` | 代码手（兼队长） | 代码实现、求解、`results.json`、所有图与表数据 | `01_OUTBOX/coder/` | ⬜ 待认领 |
| `writer` | 论文手 | 按模板填章节、图表题注、参考文献 | `01_OUTBOX/writer/` | ⬜ 待认领 |

---

## 为什么 modeler 兼「契约守护者」

有三个东西**全队共读、只能一人写**，谁都能改就出事：

1. `FACTS.md` —— 数字口径。三个人各改一套 = 三套数字，**这比数字写错更致命**。定口径本来就是建模手的活。
2. `SPEC.md` —— `results.json` 的接口，建模手与代码手的握手点。
3. `scripts/` 与 PR 合并 —— 统稿工具链，改坏全队停摆。

**为什么不给代码手（队长）**：如果一个人既能改 FACTS.md 口径、又能改 results.json schema、还能自己合自己的 PR，
那套「数字不手抄、自动回填 + 对账」的机制等于没上锁。

**队长的身份不受影响**：代码手照常管进度、定方向、催活、拍板技术选型，只是不持有改数字口径的权限。
发现问题 → 在 STATUS.md「风险/阻塞」登记，由 modeler 改。

---

## 规则

1. 分支名 `agent/<角色id>/<任务>`，角色 id 只用 `modeler` / `coder` / `writer`，**不许用昵称**。
2. 产出只落在 `01_OUTBOX/<角色id>/`；`00_CONTRACT/` 和 `scripts/` 只有 modeler 能改。
3. 认领任务 = 把 STATUS.md「待认领」里那一行整行搬到自己的分区。
4. PR 由 modeler（或其代理）合并，合并前会自动跑 `scripts/premerge_check.py`。
