# 提交信息规范

统一的提交信息让 git log 好读、好搜、好生成 changelog。

## 格式

```
<type>: <subject>

<body> （可选）
```

### type（类型）

| type | 说明 | 例子 |
|------|------|------|
| `feat` | 新功能 | `feat: 增加密码登录功能` |
| `fix` | 修复 bug | `fix: 修复登录页验证码不刷新` |
| `docs` | 文档变更 | `docs: 更新 API 文档` |
| `style` | 格式调整（不影响逻辑） | `style: 统一缩进为 2 空格` |
| `refactor` | 重构（不新增功能、不修 bug） | `refactor: 抽离用户验证逻辑` |
| `test` | 测试相关 | `test: 给登录模块补单测` |
| `chore` | 杂项（构建、工具、看板等） | `chore: alice 认领「登录页开发」` |
| `perf` | 性能优化 | `perf: 优化用户列表查询速度` |

### subject（标题）

- 用中文，简洁描述做了什么
- 句尾不加句号
- 不超过 50 个字符
- 用动词开头（增加、修复、更新、重构…）

### body（正文，可选）

- 详细说明为什么这么改、改了什么
- 每行不超过 72 字符
- 需要的话可以加 `Closes #123` 关联 issue

## 好例子 vs 坏例子

### ✅ 好的提交

```
feat: 增加手机号登录方式

支持手机号+验证码登录，验证码有效期5分钟。
新增 sendSmsCode() 和 loginByPhone() 两个接口。
Closes #42
```

```
fix: 修复登出后仍能访问受保护页面的问题

原因是 token 清除逻辑写在了路由守卫之后，
移到 logout 函数的最前面解决。
```

```
chore: bob 更新「用户数据层」进度 60%
```

### ❌ 坏的提交

```
更新              ← 太模糊，谁知道更新了啥
fix bug           ← 什么 bug？
wip               ← work in progress 不是提交信息
各种改            ← 完全没用的描述
```

## 看板更新的提交

所有对 `STATUS.md` 的修改统一用 `chore` 类型：

| 场景 | 提交信息 |
|------|----------|
| 认领任务 | `chore: <id> 认领「<任务名>」` |
| 更新进度 | `chore: <id> 更新「<任务名>」进度 60%` |
| 移到待评审 | `chore: <id> 提交「<任务名>」待评审` |
| 标记完成 | `chore: <id> 完成「<任务名>」` |
| 登记风险 | `chore: <id> 登记风险：xxx` |
| 发布公告 | `chore: 发布公告：xxx` |
