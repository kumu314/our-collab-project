# 章节稿模板（writer 用）

> **用法**：复制本文件 → 改名为 `sec<章号>_<内容>.md` → **只填空，不改结构**。
> **为什么用死模板**：三个 agent 自由发挥 = 三种风格 = 统稿时全靠人肉对齐（就是你说的"要好不少时间来改"）。
> 模板把结构、层级、用语都锁死，agent 只填内容，产出天然一致。

---

## 模板

```markdown
## <章号>、<章标题>

### <章号>.1 <子节标题>

**<一句话说清这节要干什么>**

<正文段落 1：背景/动机，3-5 句>

<正文段落 2：方法/做法，3-5 句>

其中关键量说明如下：

1. <要点一>；
2. <要点二>；
3. <要点三>。

（如图 X-X 所示 / 如表 X-X 所示）

![图X-X <中文题注>](../../01_OUTBOX/coder/fig<图号>_<内容>.png)

**<结果/结论段>**

数值结果：{{<占位符，来自 results.json>}}。

<分析：这个数说明什么，为什么是这样，2-4 句>
```

---

## 填写硬规则

| 项 | 规则 |
|---|------|
| **结构** | ⛔ 不能加/删/改小标题，只能填内容 |
| **标题层级** | 顶级用中文数字（一、二、三…），子节用 `章号.序号` |
| **数字** | ⛔ 绝不手抄。一律 `{{占位符}}`，如 `{{P1.total_cost}}` |
| **图引用** | 写「如图 X-X 所示」，⛔ 禁写 `见 xxx.png` |
| **图题注** | 从 `results.json` 的 `figures[].caption` 复制，⛔ 不自己编 |
| **编号** | 图 `图X-X` / 表 `表X-X`，**分章编号** |
| **段落长度** | 3-5 句为主，故意长短交替（别每段一样长，机器感最强） |
| **列表** | 真正的并列项才用 `1. 2. 3.`，⛔ 不用 `- ` 黑点 |

---

## 文风（去 AI 痕迹）

**禁用**：值得注意的是 / 不难看出 / 综上所述 / 随着…的不断发展 / 标志着 / 彰显了 / 充分体现了

**要做的**：
- 长句拆短句
- 一句话只说一件事
- 让数字说话，不用"显著的""极大的"这类形容词
- 敢下判断："这个方案不好，因为…"而不是永远"各有优劣"

**示例对比**：
```
❌ 值得注意的是，该算法在收敛性方面表现出了较为显著的优势。
✅ 该算法在第 10 代收敛到 {{P1.total_cost}} 元，比贪心基线低 {{P1.gain_vs_greedy}} 元。
```
