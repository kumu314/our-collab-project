# 风格统一指南

> 多 agent 协作最大的坑就是"各写各的风格"。这份文档定义统一标准，开工前先读一遍。

---

## 1. 命名规范

### 文件 / 文件夹
- 一律英文、小写、用 `-` 连接（kebab-case）
- ✅ `user-profile.ts`、`login-page.vue`
- ❌ `UserProfile.ts`、`user_profile.js`、`用户资料.js`

### 变量 / 函数
- 根据项目主语言的惯例来，**项目内统一**
- JavaScript/TypeScript：camelCase（变量、函数）+ PascalCase（类、组件）
- Python：snake_case
- CSS：kebab-case

### 常量
- 全大写 + 下划线：`MAX_RETRY_COUNT = 3`

---

## 2. 代码格式

### 缩进
- 统一 2 空格（不用 tab）
- 配置 `.editorconfig` 或 `.prettierrc` 自动格式化

### 行宽
- 代码：100 字符左右，不超过 120
- Markdown：一行一句话（方便 diff）

### 引号
- 字符串统一用单引号（JS/TS）或双引号（Python），项目内统一
- JSON 必须双引号

### 分号
- JavaScript/TypeScript：加分号

---

## 3. 注释规范

### 代码注释
- **为什么**比**做了什么**重要——代码已经说了做了什么
- 复杂逻辑处加注释，解释思路
- 公共 API 必须有 JSDoc / docstring

### TODO 注释
统一格式：
```
// TODO(<agent-id>): <要做的事>  — 2026-09-04
```
例子：
```js
// TODO(alice): 增加超时重试逻辑 — 等基础框架稳定后做
```

---

## 4. Markdown 文档规范

### 标题层级
- `#` 文档标题（只有一个）
- `##` 一级章节
- `###` 二级章节
- 不要跳到四级及以下，需要的话考虑拆文档

### 列表
- 用 `-` 不用 `*`
- 有序列表用 `1.` 就行，编号让渲染器自己算

### 中文排版
- 中文和英文/数字之间加空格：`用 Git 管理` 不是 `用Git管理`
- 标点用中文标点，代码和命令除外

---

## 5. 目录结构约定

```
src/
├── components/      ← 可复用组件（UI 层）
├── pages/           ← 页面级组件
├── services/        ← 接口请求、业务逻辑
├── utils/           ← 工具函数
├── types/           ← 类型定义（TS 项目）
├── assets/          ← 静态资源（图片、字体）
└── styles/          ← 全局样式
```

每个模块内部保持同样的结构，让人一看就知道东西在哪。

## 7. 接口约定

模块之间的接口是协作的生命线。

### 函数 / 方法
- 先定签名（参数名、类型、返回值），再写实现
- 入参不超过 3 个，多了用对象包起来
- 有副作用的函数，名字要体现出来（比如 `saveUser`、`fetchData`）

### 数据格式
- 时间：统一 ISO 8601 字符串（`2026-09-03T12:00:00Z`）
- 金额：整数（分），不用浮点
- ID：字符串类型，不假设是数字

### API 响应
统一结构：
```json
{
  "code": 0,
  "data": { ... },
  "message": "ok"
}
```

## 8. 错误处理

- 不要静默吞掉错误，至少打日志
- 用户可见的错误信息要友好，不要把堆栈直接抛给用户
- 内部错误要有错误码，方便排查

## 10. 风格不一致怎么办

1. **以主干为准**：main 分支上的现有风格就是默认风格
2. **不要在功能 PR 里顺手改风格**——单独开一个 style 类型的 PR
3. **拿不准就问**：在「风险/阻塞」里提，或者找整合人确认
4. **统一由整合人拍板**：争议不辩论，整合人说了算，后面再优化
