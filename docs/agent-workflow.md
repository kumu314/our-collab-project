# Agent 标准工作流程

每个 Agent 接到任务后，严格按以下 7 步走。

---

## 第 1 步：同步 & 读看板

```bash
git checkout main
git pull origin main
```

打开 `STATUS.md`，确认：
- 有没有人已经在做类似的任务（避免重复劳动）
- 有没有依赖的任务还没完成
- 有没有公告或风险需要注意

---

## 第 2 步：认领任务

1. 把任务从「待认领」移到「进行中」
2. 填上你的 agent-id、进度（0%）、预计完成时间
3. 提交并推送：

```bash
git checkout -b agent/<your-id>/<task-name> main
# 编辑 STATUS.md
git add STATUS.md
git commit -m "chore: <your-id> 认领「<任务名>」"
git push origin agent/<your-id>/<task-name>
```

> **命名提示**：任务名用短横线连接的英文，比如 `login-page`、`user-api`

---

## 第 3 步：理解接口约定

开工前，先搞清楚：
- 你负责的模块，**输入**是什么（从哪来、什么格式）
- 你负责的模块，**输出**是什么（给谁、什么格式）
- 涉及哪些文件、哪些目录

如果接口还没定，先在「风险/阻塞」里登记，找整合人确认，**不要边猜边做**。

---

## 第 4 步：干活（只在你的分支上）

### 规则
- 只改你负责的模块文件
- 不要顺手改别人模块里的"小问题"——提 issue 或在 PR 评论里说
- 每做完一个小阶段（比如一个功能点），提交一次

### 提交频率建议
- 小功能：做完一个提交一次
- 大功能：每 1-2 小时提交一次
- 提交信息规范见 `commit-convention.md`

### 每天至少推一次
即使没做完，也每天把代码推到远端，防止本地丢失：
```bash
git push origin agent/<your-id>/<task-name>
```

---

## 第 5 步：更新进度

每完成一个里程碑，更新 `STATUS.md` 里的进度百分比：

```bash
# 编辑 STATUS.md，把进度从 30% 改成 60%
git add STATUS.md
git commit -m "chore: <your-id> 更新「<任务名>」进度 60%"
git push origin agent/<your-id>/<task-name>
```

遇到问题或阻塞，也及时写到「风险/阻塞」里，不要闷头扛。

---

## 第 6 步：提交 PR

任务完成后：

1. 确保你的分支和 main 同步：
   ```bash
   git fetch origin
   git rebase origin/main
   # 有冲突就解决，解决不了找整合人
   ```

2. 跑一遍基本检查（根据项目类型）：
   - 代码项目：编译通过、测试通过、lint 通过
   - 文档项目：格式检查、无死链

3. 推送到远端：
   ```bash
   git push origin agent/<your-id>/<task-name>
   ```

4. 在 Git 平台发起 PR，按模板填写

5. 在 `STATUS.md` 里把任务从「进行中」移到「待评审」，附上 PR 链接

---

## 第 7 步：响应评审

- 评审意见及时改，改完推送到同一分支，PR 会自动更新
- 每条评审意见处理完在评论里回复「已修复」或说明原因
- PR 合并后，把 `STATUS.md` 里的任务移到「已完成」

---

## 紧急情况处理

### 发现别人也在改同一个文件
1. 先停手，在「风险/阻塞」里登记
2. @对方 agent 或整合人协调
3. 不要硬上——后面合并冲突会更痛苦

### 任务做不完 / 难度超预期
1. 及时在「风险/阻塞」里说明情况
2. 更新预计完成时间
3. 建议拆分任务，先交能用的版本

### 需要别人配合
1. 在「风险/阻塞」里写清楚需要谁、做什么、什么时候要
2. 也可以在 PR 评论里 @对方
